목적: 무엇을 위한 모듈인가

병원 밖에서 만들어진 ECG 모델이 우리 환자에서 얼마나 맞는지는 돌려 보기 전에는 알 수 없습니다. 그런데 모델마다 입력 형식, 런타임, 출력이 달라서 비교 가능한 조건으로 돌리는 것 자체가 일입니다.

  • MI-VAL은 모델을 코드에 쓰지 않습니다. 모델은 카드(JSON) 하나, 연구 설계는 study(YAML) 하나로 선언하고, 6단계 파이프라인은 그 두 파일만 읽습니다.
  • 모델을 하나 더 검증하는 것은 카드 한 장을 registry에 넣는 것이고, 연구 질문을 바꾸는 것은 study 파일을 고치는 것입니다. 코드가 바뀌었다면 그 자체가 기록할 결과입니다.
  • 목표는 모델 12개 × 기관 2개(MIMIC → 신촌). 이번은 LVEF 과제로 4개 모델을 6단계 끝까지 통과시킨 기록입니다.

구성: 6단계, 파일로만 이어진다

  • 단계는 파일로만 이어집니다. 한 단계의 산출물 경로가 다음 단계의 --input이고, 그 파일의 체크섬이 다음 실행의 config_hash에 들어갑니다.
  • test split은 Models 단계에서 딱 한 번만 열립니다. 임계값은 dev에서 refit하고, 5·6단계는 그 예측 파일을 자르기만 합니다.

이번 과제의 모델 4개

  • 12유도 10초는 넷이 같지만 표본율이 100·250·500 Hz로 셋이고, HeartWise는 저자 코드의 1/0.0048 이득을 gain으로 선언합니다. 이 차이는 전부 카드에 있고 코드에는 없습니다.

실제 실행 1: 데이터 소스와 Retrieve

  • ECG: MI-CDM(MIMIC-IV OMOP) image_occurrence → S3 DICOM 800,035파일 99 GB를 서버 /scratch에 캐시.
  • LVEF 라벨: 협업자가 OMOP measurement로 적재한 147,431행(concept 3027172, LOINC 10230-1). ECG와 person_id + 날짜로만 연결.
  • 같은 날(0일)과 다음 날(+1일)이 87,393건으로 가장 많고, 창 양끝(±7일)은 3천 건대.
  • DB에 인덱스가 하나도 없어 partial index 하나를 만들고 나서야 20초에 돕니다. 이것도 실행 기록에 남겼습니다.

실제 실행 2: Profile과 1,000건 샘플

  • 샘플은 image_occurrence_id가 가장 작은 1,000건입니다. 무작위도 층화도 아닙니다. 목적은 6단계가 실제 데이터로 끝까지 도는가였고, 뒤에 나오는 수치는 성능 추정치가 아닙니다.
  • split은 전체 코호트의 cohort_split을 그대로 조인했으므로 dev/test 누수는 없습니다.
  • 전체 코호트 실행 추정(샘플 실측 기준): preprocess 26분(130 GB), models 3~4시간(xECG probe가 병목), evaluate 0.5~2시간. 이번에는 돌리지 않았습니다.

실제 실행 3: Preprocess, recipe 4개

  • DICOM에서 MDC 코드로 유도를 맞춰 읽고(loader: dicom), 카드 계약대로 recipe를 컴파일합니다. 같은 계약이면 recipe를 공유하므로 모델 5개에 recipe 4개, 1,000건에서 제외 0건.
  • perturbation은 선언만 실행됩니다. 표본율이 셋이라 공통 열화 격자를 못 잡아 기준선만 선언했고, 그마저도 지금 어느 stage도 격자를 돌리지 않습니다(grid json만 기록). 열화 곡선은 이번 결과에 없습니다. L2로 기록.

실제 실행 4: Models, 6 arm을 env 2개로

  • study는 하나지만 카드의 runtime.env가 둘이라 models를 env마다 한 번씩 돌리고 manifest를 따로 남겼습니다(ecgfounder env 46초, xecg env 72초, 1,000건). 첫 실행에서 상대 경로 버그(A-10) 하나를 찾아 고쳤습니다.

결과 1: 분류 (LVEF ≤ 40, test 206건)

  • 단일과제 HeartWise와 foundation probe 둘의 AUROC는 신뢰구간이 겹칩니다. 206건으로는 순위를 말할 수 없고, 세 arm이 같은 코호트·같은 split·같은 지표로 한 표에 나온다는 것이 이 슬라이드의 내용입니다.
  • 기울기 2.1·1.7은 확률이 과소 분산됐다는 뜻입니다. HeartWise는 저자 코호트 단위 스펙트럼 정규화를 적용하지 않은 상태(L2-2)라 예상된 방향입니다.

결과 2: 회귀 (LVEF %, test 206건)

  • 회귀는 새 stage가 아니라 label_def: value 하나로 들어갑니다. 예측 파일의 pred_value 열, 지표 범주의 MAE·RMSE·R², 그리고 regression_cuts: [40]이 회귀 예측을 분류 지표로도 읽어 줍니다.
  • ECGFounder probe는 순서는 맞추는데(AUROC@40 0.89) 값은 못 맞춥니다(R² 0.08). 산점도에서 예측이 52 근처에 몰려 있습니다. 선형 head가 target 크기(LVEF 15~80)까지 못 올라간 것이라, 목표값 표준화(L1 후보)인지 lr 격자 문제인지 전체 실행 전에 봅니다.

실제 실행 6: Misclassification

  • 임계값이 refit_sens95(민감도 95% 보장)라 오분류는 거의 전부 FP입니다. FN은 세 모델 통틀어 3건이고 전부 LVEF 21인 같은 환자입니다. 리뷰 1순위.
  • 회귀 arm은 확률이 없어 지금 selector 4종의 대상이 아닙니다. 회귀 잔차 상위를 보려면 type: residual이 필요합니다(L1 후보). verdict 어휘가 아직 STEMI용(stemi_mimic, reperfused)인 것도 study별로 열어야 합니다(L0).

이번 실행에서 프레임워크가 배운 것

  • 모델 4개를 넣는 데 카드 4장과 study 1개면 됐고(L0), 실데이터가 드러낸 버그 4건을 고쳤으며(L1, 각각 회귀 테스트), 코드로 풀지 않고 보고만 한 것이 4건입니다(L2). 이 비율이 프레임워크의 성적표입니다.

다음

  • 전체 코호트 실행(182,927 ECG). 추정 5~7시간. 그 전에 linear probe의 feature 캐시(L1)를 넣으면 xECG가 3~4시간에서 15분 정도로 줍니다. 내부 CV 11번의 fit이 매번 backbone을 다시 돌리기 때문입니다.
  • 연구 결정 2건: label_sens2(±30일)가 지금 구조에서 label_primary와 항상 같아지는 문제(A-9), 그리고 perturbation 열화 격자를 카드별로 둘지(L2).
  • misclassify 보강: 회귀 잔차 selector, study별 verdict 어휘, preprocess_index를 넘겨 파형 그림까지.
  • 신촌 전이: 같은 study.yaml, 같은 카드 4장, site만 바꿔서. MIMIC에서만 맞던 가정이 있으면 거기서 드러납니다.
