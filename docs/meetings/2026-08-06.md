# MI-VAL 회의록

- 일시: 2026-08-06
- 다음 미팅: 2026-08-14 금요일 오후 2시로 해석됨

## 1. 연구 전제

- MI-CDM이 ETL되어 있는 상태를 전제로 한다.
- cohort는 ATLAS를 활용해 정의한다.
- ATLAS에서 index date와 observation window 등을 설정한다.

## 2. 연구 파이프라인

파이프라인은 규리T 버전으로 고정하며 다음 6단계로 구성한다.

### 1) Retrieve

- MI-CDM에서 실제 DICOM 파일을 가져오는 모듈이다.
- 시작점은 `person_id`, `image_occurrence_id`, `local_path`다.

### 2) Profile

- 가져온 데이터를 전처리 전에 연구자가 확인할 수 있게 한다.
- 연구 초기 단계에서 데이터 특성을 파악할 수 있어야 한다.
- 민성: Fingerprint 버전을 기반으로 검토한다.

### 3) Preprocess

- 전처리 방식은 추가 검토가 필요하다.
- MI-CDM ETL validation에서 사용한 전처리 방식과 pydicom 기반 전처리 방식을 비교한다.

### 4) Models

- 모델 실행 과정에서 사용자 자유도를 어느 수준까지 허용할지 결정한다.
- 민성: TaskSpec 버전을 기반으로 검토한다.
- hyperparameter 설정 방식과 task/model 정보 관리 방식을 정의한다.
- 참고 대상: RSNA, ATLAS `model.json`, `.pth`, GitHub, Hugging Face.

### 5) Evaluation

평가 과정과 지표를 다음 세 범주로 구분하는 방향을 검토한다.

- Discrimination
- Calibration
- Interpretation

### 6) Misclassification

- 모델 오분류 사례와 오류 분석 결과를 자동으로 확인할 수 있게 한다.

## 3. Technical Report

Retrieve부터 Misclassification까지의 전체 과정과 결과를 하나의 Technical Report로 정리해 연구자에게 제공하는 방향을 검토한다.

## 4. ATLAS와 Multimodal Framework의 차이

### ATLAS

- 보수적인 연구자가 사용하는 비교적 안정적인 환경이다.
- 요구사항과 구조가 크게 변하지 않을 가능성이 높다.

### Multimodal

- 기술과 요구사항이 지속적으로 변할 가능성이 높다.
- 요구되는 specification의 범위도 매우 넓다.

## 8. 추가 Context

- 관련 repository: YouLab organization의 `mimic-iv-ecg-to-dcm`.
- 관련 파일: `mimic-ecg-metadata.csv`.
- Channel Definition Sequence에는 일반적인 12-lead ECG 기준 12개 channel item이 있다.
- DICOM마다 channel 순서가 다를 수 있으므로 DICOM 내부 순서대로 `image_feature_value_order`에 저장한다.
- `image_feature_value_order`가 없는 값은 개별 channel이 아니라 전체 ECG에 대한 값이다.
- channel별 값: `ChannelLabel`, `ChannelSensitivity`, `ChannelSensitivityUnitsSequence`, `ChannelBaseline`.
- `SamplingFrequency`는 repository 문서 기준 waveform-level 값이다.
