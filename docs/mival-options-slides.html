이 프레임워크에서 "옵션"이 사는 곳

선택은 코드가 아니라 두 종류의 파일에 있습니다. 모델을 추가하는 것은 ModelCard JSON 하나를 넣는 것이고, 연구 설계를 바꾸는 것은 study.yaml을 고치는 것입니다. 실행 코드에는 모델 이름이 등장하지 않습니다.

  • 3–6단계는 지금 실행 가능합니다. 1–2단계는 Data4Life · MI-CDM 접근에 막혀 있습니다.
  • 기본값이 없는 항목이 몇 개 있습니다. 코드가 알 수 없는 사실이기 때문입니다 — 13번 슬라이드.

두 모델의 카드

아래는 registry/models/*.json에 실제로 선언된 값입니다. 이 표가 나머지 모든 옵션을 결정합니다.

  • 두 모델은 같은 프로세스에서 돌 수 없습니다. Python 3.9 + TF 2.7 환경과 Python 3.10 + torch 환경이 분리돼 있어, 단계마다 환경을 바꿔 실행합니다.
  • 붉게 표시된 두 칸(positive_index: null, feature_layer: null)이 다음 슬라이드의 빈칸을 만듭니다.

실행 가능한 arm — 칸을 눌러보세요

spec §2.5가 계획한 arm은 넷입니다: PROPHECG inference_only, PROPHECG linear_probe, ECGFounder linear_probe, ECGFounder full_finetune. 이 중 하나가 지금 막혀 있습니다.

3단계 Preprocess 옵션

  • recipe_id는 선택 항목이 아닙니다. 계약과 원본 metadata의 함수로 자동 산출되며, 입력계약이 같은 두 카드는 tensor를 공유합니다. PROPHECG(8유도)와 ECGFounder(12유도)는 계약이 다르므로 각자 tensor를 갖습니다.
  • perturbation tensor는 디스크에 쓰이지 않습니다. 4단계 dataloader가 그때그때 적용합니다.

Perturbation 축 — 축을 눌러보세요

축 수준은 계약 상대적입니다. 계약보다 높은 수준은 아무것도 제거하지 않아 baseline과 비트 단위로 같은 셀이 되므로 check_grid_against_contract가 거부합니다.

4단계 Models — arm 선언

  • partial_unfreeze는 unfreeze_groups가 필수입니다. 무엇을 녹였는지가 기록이어야 하기 때문입니다.
  • 같은 (model_id, training_mode, label_def) 조합을 두 번 쓸 수 없습니다 — 같은 run_key를 두 번 쓰게 됩니다.
  • early_stopping_fold를 적지 않으면 자동으로 잡힙니다. 적으면 그 fold가 조기종료 전용이 됩니다.

hyperparameter 기본값

  • 학습률이 모드마다 3자리씩 다른 이유: 얼어붙은 backbone 위의 head는 큰 학습률을 견디지만, 사전학습된 backbone은 견디지 못합니다 (Howard & Ruder 2018).
  • pos_weight 기본이 1.0인 이유: 재가중은 예측 위험도를 부풀려 calibration을 망칩니다. STEMI 미검출의 비대칭 비용은 threshold 정책이 담당합니다.
  • 모르는 키를 쓰면 거부합니다. 조용히 무시하면 grid의 두 후보가 실제로는 같은 설정이 됩니다.

운영 임계값 정책 3종

  • 임계값은 절대 test에서 고르지 않습니다. SplitScores가 split 이름을 들고 다니고, refit 함수는 dev가 아니면 거부합니다 — 호출자가 기억할 필요가 없습니다.
  • 4단계가 고른 임계값을 5·6단계가 함께 씁니다. 6단계의 "임계값 근처 사례"가 5단계가 보고한 것과 다른 결정 규칙의 경계이면 의미가 없기 때문입니다.

5단계 Evaluation 옵션

  • 모델 간 비교는 DeLong이 아니라 paired bootstrap of difference입니다. 환자당 ECG가 여러 개라 clustered 데이터이고, DeLong은 그 경우 부적절합니다.
  • 산출물은 long format이라 축이 늘어도 스키마가 변하지 않습니다.

6단계 Misclassification — selector를 눌러보세요

축 하나가 모델마다 다른 뜻인 경우

perturbation은 계약이 적용된 뒤의 tensor에 적용됩니다. 그래서 같은 축 수준이 두 모델에 서로 다른 손상을 의미할 수 있습니다. 결과표에 반드시 함께 적어야 합니다.

  • amplitude_scale이 정규화 모델에 무효인 것은 버그가 아니라 옳은 답입니다. 실제로 잘못 보정된 ECG도 모델 자신의 정규화를 통과하므로, 재정규화하지 않으면 배포 환경에서 일어날 수 없는 실패를 보고하게 됩니다.

기본값이 없는 것 — 반드시 선언

코드가 알 수 없는 사실에는 기본값을 두지 않았습니다. 틀린 기본값은 없는 것보다 나쁩니다 — 칸을 채우고 보고까지 되기 때문입니다.

  • 같은 이유로, hparams에 모르는 키를 쓰면 거부합니다. 조용히 무시하면 서로 다르다고 기록된 두 grid 후보가 실제로는 같아집니다.
